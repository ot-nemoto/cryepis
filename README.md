# cryepis

GitHub プロフィールに Pin した Gist の中身を、GitHub Actions の定期実行で生成・更新する仕組みです。
ネタ（Pin に載せる内容）ごとにスクリプトと workflow を持ち、今後ネタを追加していく想定です。

## ネタ一覧

| ネタ | Pin する Gist | 更新 | 説明 |
|---|---|---|---|
| [勇者の冒険（テキスト RPG）](#勇者の冒険テキスト-rpg) | ランキング 1 つ | 毎日 JST 7:17 | 勇者たちがギルドの依頼をこなして育っていくのを眺める RPG。3 か月ごとのシーズン制（アイテムだけ持ち越す） |

## 共通の仕組み

- workflow・スクリプト・ファイルの関係と、各ファイルの使い道は [docs/DATA_FLOW.md](docs/DATA_FLOW.md) の図を参照
- `.state/` 配下のファイルの JSON 構成と項目の意味は [docs/STATE_FORMAT.md](docs/STATE_FORMAT.md) を参照
- セットアップ（Gist・PAT・Secrets / Variables）は [docs/SETUP.md](docs/SETUP.md) を参照
  （ネタを追加したら、これらのドキュメントにも追記する）
- Gist の更新には `gist` スコープの Classic PAT（Secret `GIST_PAT`）を使う。Gist の ID は `.state/` のファイル（RPG は `board.json`）に記録する
- Pinned カードには Gist の**名前順で先頭のファイル**の、先頭 5 行（見出し + 4 行）ほどしか出ず、1 行 55 桁前後で切れる。
  各ネタはこの範囲に収まるように出力する（Gist のファイルは 1 つだけにする。1 行は `common.LINE_MAX` = 49 桁まで）
- 記録用のデータは `.state/` に置き、workflow の最後に github-actions[bot] 名義で master に直接コミットする（PR は通さない）
- `.state/last-run` は keepalive 用。毎日コミットし、60 日無活動による scheduled workflow の停止を防ぐ
- 標準ライブラリのみで動く（Python 3.12）。GitHub API・Gist の更新・表示幅の計算は `scripts/common.py` にまとめている

## テスト・リンター・フォーマッター

```sh
python -m unittest discover -s tests   # テスト（標準ライブラリだけで動く）
pip install ruff==0.17.4               # リンターとフォーマッター（開発と CI でだけ使う）
ruff check .                           # リンター（--fix で直せるものは直す）
ruff format .                          # フォーマッター（インデントはスペース 2。--check で確かめるだけ）
```

- 設定は `pyproject.toml`（Ruff）と `.editorconfig`（エディタ。インデントはスペース 2）
- PR を作った・更新したとき（と master への push・毎日の実行のあと）に、サイト公開のワークフロー（`.github/workflows/pages.yml`）が CI としてリンター・フォーマット・テストを確かめる（PR では公開しない）

## ネタを追加するとき

1. `scripts/` にスクリプトを、`tests/` にテストを追加する（Gist の更新は `common.update_gist` を使い回せる）
2. ネタごとに `.github/workflows/` に workflow を作る（`hero-adventure.yml` を参考にする）
   - 最初に Test ステップ（`python -m unittest discover -s tests`）を置く
   - `.state/` に書くなら `permissions: contents: write` とコミットのステップを用意する。
     keepalive（`.state/last-run`）はどれか 1 つの毎日の workflow で更新すれば足りる（今は `hero-adventure.yml`）
3. public Gist を作り（ファイルは 1 つ）、ID を管理するしくみ（`.state/` のファイルなど）を用意して Pin する
4. ドキュメントを更新する: この README の「ネタ一覧」とネタごとの節、docs/SETUP.md（Gist・Variable）、
   docs/DATA_FLOW.md（図・ファイルの表）、`.state/` に書く場合は docs/STATE_FORMAT.md（データ形式）

## 勇者の冒険（テキスト RPG）

MAP の上で勇者たちが毎日それぞれ動き、町のギルドの依頼をこなしながら育っていく RPG を Gist に表示します。
ゴールはなく、成長を眺める RPG です（設計は [docs/SEASON_DESIGN.md](docs/SEASON_DESIGN.md)。いまは第 1 段階のプロトタイプ）。
勇者は最大 30 人まで同時に冒険できます。見る場所は次のとおりです。

- **ランキングの Gist**（Pin する。Gist はこの 1 つだけ）: 今のシーズンの進み具合と、レベル・討伐数・依頼達成のランキング。
  本文には勇者ごとの短い欄もある。最初の毎日の実行で自動的に作られる
- **サイト「クリエピス戦記」**（GitHub Pages。https://ot-nemoto.github.io/cryepis/ ）: 最初のページはストーリー（`world/story.md` の物語・世界・歴史と、いまの冒険の状況）。ほかに地図（拡大・移動ができ、町や勇者にマウスを乗せると説明が出る。勇者の札から詳細へ飛べる。道の上の数字は移動にかかる行動回数）、
  ランキングと今日の出来事、勇者の一覧、町の情報（全部の町を地方ごとのタブで切り替える。説明・ギルドの規模・特産品・店・レア・道。開放していない町は説明とギルドの規模だけ）、町ごとのギルドの掲示板（地方ごとのタブ。レアリティで絞り込める）、開放した地域で手に入るアイテムの一覧（装備の種類ごとのタブ。レアリティで絞り込める）、勇者ごとの詳細（ステータス・装備・持ち物・依頼・直近 30 日の冒険の記録・歴代のシーズンの記録）。
  `scripts/website.py` が `.state/` と `world/` から書き出し、`pages.yml` が毎日の実行・勇者の登録・引退のあとと、master への push のあとに公開する（書き出したファイルはコミットしない）

ランキングのカード:

```
🏆 シーズン1  Day 40/90  勇者5人
Lv   🥇カイ 13 🥈ゴール… 13 🥉ボブ 13
討伐 🥇アリス 59 🥇ボブ 59 🥉カイ 57
依頼 🥇CASSIA 16 🥈ゴール… 13 🥉ボブ 12
📰 カイ: 依頼達成！森の町へ荷物を届ける（+72EXP …
```

カードでは名前を表示幅 8（全角 4 文字）までに切り詰めます。ランキングの Gist を開くと、全員の順位（レベル・討伐数・依頼達成・レアアイテム）、
今日の出来事、勇者ごとの欄、歴代のシーズンの 1 位が見られます。勇者ごとの欄はこんな形です。

```
■ アリス  Lv.12  📍 迷いの森 🎯 ウルフ 1/4
  HP 117/123  攻33 防16  1587G  回復薬 3
  装備: ★★狩人の短剣/★鉄の兜/★幸運のお守り
  レア: ★★狩人の短剣
  今日: ウルフを倒した (+17EXP)、木漏れ日が揺れている
  詳細: https://<owner>.github.io/<repo>/heroes/h1.html
```

サイトの勇者ごとの詳細のページ（`heroes/<id>.html`）の先頭:

```
⚔️ アリス Lv.12  S1 Day 40
📍 迷いの森 🎯 ウルフ 1/4
HP ██████████ 117/123  攻33 防16  1587G
装備: 鉄の剣 / 鎖かたびら / 幸運のお守り
今日: ウルフを倒した (+17EXP)、木漏れ日が揺れて…
```

続けて、ステータス・装備・持ち物、今シーズンの成績、直近 30 日の冒険の記録、歴代のシーズンの記録が載ります。

### 勇者を増やす・引退させる（手動実行）

| workflow | 入力 | すること |
|---|---|---|
| *New game (add a hero)* | 勇者の名前 | 勇者管理シート `.state/heroes.json` に登録し、状態を作る（Gist は作らない。詳細はサイトの勇者のページ）。冒険は次回の毎日の実行から進む |
| *Retire hero* | 勇者の ID（`h1` など）または名前 | 勇者を引退させる（毎日の更新の対象から外れ、ランキングにも出なくなる。状態は残り、サイトの詳細のページも残る。枠が 1 つ空く） |

- 手動実行は 1 件ずつ、終わってから次を実行する（`.state/` への書き込みを直列にするため、待機中に別の実行が起動すると先の待機分が取り消される）
- 現役の勇者は最大 30 人（`MAX_HEROES`）。引退した勇者は数えない。同じ名前の現役の勇者は作れない。名前は表示幅 16（全角 8 文字）まで
- 勇者管理シート `.state/heroes.json` に、勇者の ID・名前・作成日・現役かどうかが入る

### 進み方

- **世界はオルドラ**（[docs/WORLD.md](docs/WORLD.md)）: 3 つの大陸と島々に 25 の町。町と町は**陸路**と**航路**（船）でつながり、道ごとに移動にかかる行動回数が決まっている。ダンジョン（7 か所）は地図に載っているが、まだ入れない（第 2 段階）
- **少しずつ開放する**: いまは**南大陸だけ**（サリナ・エクエス・ムラリス・カルン）を開放していて、勇者はこの中だけを旅する。ほかの町は地図に出すが、道は描かず通れない（`map.json` の `open`）。開放していない町の依頼とレアのアイテムは、データから外している
- **場所は町だけ**（野外の場所はない）。道を 1 行動進むごとに、道の地形（草原・森・砂漠・雪原・海など）に合った魔物に出会ったり、宝箱を見つけたりする
- **魔物の強さはどこでも同じ**で、地形ごとに性質（先手・毒・群れ・凶暴・硬い・盗み）が違う。強い敵はダンジョンにだけ出る（第 2 段階）
- **最初の町はランダム**: 開放した町のうち 3 つ（`starts`。サリナ・エクエス・カルン）から、勇者ごとに決める。シーズンが変わると決め直す
- 1 日の**行動回数**は毎日同じ（`world/season.json` の `actions_per_day`、今は 3 回）。何が起きるか（魔物・宝箱・景色など）が乱数で決まる
- 町に着くと HP が全回復し、店で今より良い装備と回復薬を買う。ギルドの掲示板（町ごとに全員共通。日をまたいで残る）から、
  依頼を受ける。**依頼を受けるのは 1 日 1 回**で、受けるのに行動回数は使わない。依頼がなければ、となりの町へ旅をする（報酬なし）
- 依頼ごとに**必要な行動力**が決まっていて、毎日の行動回数でこなしていく（何日かかってもよく、期限はない。失敗するのは力尽きたときだけ）
  - 配達: 届け先までの距離（道の行動回数の合計）
  - 討伐: 行き（狩り場まで。道の長さの半分、最大 2）＋ 討伐の数（1 行動で目的の魔物と 1 回戦う）＋ 帰り
- 依頼が終わってその日の行動回数が余ったら、町の周りを散策する（道の出来事だけが起きる）
- ギルドの掲示板は町ごとに枠の数が決まっていて（王都 6、港や大きな町 5、ふつうの町 4、小さな村や砦 3。`map.json` の `quests_per_day`）、**早い者勝ち**。ほかの勇者が受けた依頼は受けられず（受注中）、誰も受けないまま 3 日たった依頼は入れ替わる（`season.json` の `quest_open_days`）。達成された依頼は翌日に新しい依頼に入れ替わり、失敗した依頼は翌日にまた受け付ける。受けられる依頼がなければ、となりの町へ旅に出る。毎日、勇者を進める順番を混ぜるので、いつも同じ勇者が先になることはない
- ギルドには、町の特色に合わせた**町の依頼**と、どの町にもある**共通の依頼**がある。依頼にはレアリティ（★〜★★★★）があり、★ が多いほど出にくく、報酬が多く、レアのアイテムが出やすい（[docs/WORLD.md](docs/WORLD.md)）
- 依頼は**討伐**（町から出る道の 1 本の近くで、その道に出る魔物を指定の数だけ倒し、町に戻って報告する）と**配達**（別の町へ届ける。報告は届け先の町）。報告すると経験値・お金と、
  確率でアイテムがもらえる
- 道の出来事は、戦闘・宝箱（common の装備・お金・回復薬）・景色のどれか（起こりやすさは `season.json` の `road_events`）
- 宝箱と依頼の報酬で出る common の装備は、**開放した地域のもの**（開放した町の店で売っている品）だけ。ほかの地域の特産品は出ない
- 道の途中で HP が少なく回復薬もないときは、引き返したほうが近ければ引き返す。力尽きたら依頼は失敗になり、最後に寄った町で目を覚ます（お金は減らない）
- 手に入れたアイテムはすべて持ち物に入り、部位（武器・兜・盾・装飾品。鎧はない）ごとにいちばん強いものを自動で装備する
- **シーズン**は 3 か月（`world/season.json` の `start` と `months`）。シーズンが変わると記録を残し、
  **アイテム以外**（レベル・お金・回復薬・位置・依頼）を最初に戻す。アイテムは多少の助けになる程度に抑えている
- 乱数は「日付＋シーズン＋勇者の ID」を種にするので、勇者ごとに展開が違う。同じ日に何度実行しても結果は同じで、その日の分を処理済みなら進めない（Gist の表示だけ更新する）
- workflow が動かなかった日は、次の実行でさかのぼって 1 日ずつ進める（最大 7 日分）
- 1 人の勇者の更新（Gist の API エラーなど）が失敗しても、ほかの勇者は進める（失敗した勇者があれば workflow は失敗で終わる）
- 始めるには Secret `GIST_PAT` を登録して（ランキングの Gist に使う）、*New game* を実行する（[docs/SETUP.md](docs/SETUP.md)）。勇者がいない間、毎日の実行は何もしない

### 世界を広げる（world/ の編集）

| ファイル | 中身 |
|---|---|
| `world/season.json` | シーズンの長さ・初期ステータス・レベルアップ・1 日の行動回数・回復薬・宝箱のドロップ表など |
| `world/map.json` | 場所（町・ダンジョン）と道、開放した町（`open`。勇者が行ける町。ほかの町への道は描かず通れない）、最初の町の候補（`starts`。開放した町から）、地図の大きさとベースの地図（`layout`）。町には名前・呼び名（`alias`）・地域（`region`）・説明（`text`。サイトの町のページに出す）・店・地図の座標（`pos`。1600×1000、北が上）。道には種類（`kind`: 陸路 `land`・航路 `sea`・ダンジョンへの道 `trail`）・行動回数（`distance`）・地形の割合（`terrain`。出る魔物が決まる）・地図に描く線（`path`）。地方（`areas`: ID・名前・英語名）と、場所ごとの地方（`area`）と英語名（`en`）もある。いまは町 25（開放 4）・ダンジョン 7・陸路 24・航路 3（開放した道は陸路 4） |
| `world/map-base.svg` | ベースの地図（地形の絵） |
| `tools/worldgen/` | 地図づくりのスクリプト。`python tools/worldgen/make.py` で地形・陸路・航路・行動回数を作り直し、`world/map.json` と `world/map-base.svg` を書き出す（町の配置は `places.py`、名前は `names.py`、山脈・地域・川は `terrain.py`） |
| `world/monsters.json` | 魔物（出る地形 `terrain` と性質 `trait`）と、性質の一覧（`traits`） |
| `world/items.json` | アイテムと珍しさ（common / rare / epic / legendary。印は ★〜★★★★ で、依頼のレアリティと同じく ★ から始まる）。店で売るもの（common）は `price` を書く。レア（rare 以上）は `towns` に書いた町の依頼の報酬でしか出ない（レベルの制限なし）。町ごとの特産とレアは [docs/WORLD.md](docs/WORLD.md) |
| `world/quests.json` | ギルドの依頼。1 行動あたりの報酬（`reward`）、レアリティ（`ranks`: ★〜★★★★ の出やすさ・報酬の倍率・アイテムのドロップ表）、共通の依頼（`templates`）、町ごとの依頼（`towns`: 名前・内容・ギルドの言葉。開放した町だけに書く。いまは南大陸の 4 町で 16 件） |
| `world/story.md` | サイトの最初のページ（ストーリー）の文。Markdown の一部（`#`・`##` の見出し、`-` の箇条書き、`|` の表、`**太字**`、段落）が使える。物語を書き足すときはここを編集する |

- 参照はすべて ID。編集したら `python -m unittest discover -s tests` で確かめる（`tests/test_world.py` がデータの誤りを、
  `tests/test_game.py` の BalanceTest がシーズン末のレベルや依頼の成功率を調べる）
- データに誤りがあると毎日の実行の Test で止まり、その日の冒険は進まない（壊れたデータで進むことはない）
- 場所やアイテムを消しても、勇者の状態は壊れない（消えた場所にいる勇者は最初の町に戻り、消えた依頼は取り消す）
- アイテムが強すぎると検証で止まる（部位ごとの最強装備の合計が、`balance_level` での基本能力値の `item_power_rate` を超えたとき）

| ファイル | 役割 |
|---|---|
| `world/` | 世界のデータ（上の表） |
| `scripts/world.py` | `world/` の読み込みと検証、最短経路の計算 |
| `scripts/game.py` | 1 日分の進行（依頼・戦闘・アイテム・シーズンの切り替え）と、勇者の状態の読み書き |
| `scripts/mapsvg.py` | 地図の画像（SVG）を描く。ベースの地図（`layout.background`）があれば一番下に敷く。作り方は [docs/BASE_MAP.md](docs/BASE_MAP.md) |
| `scripts/website.py` | GitHub Pages のサイト（ストーリー・地図・ランキング・勇者・町・ギルド・アイテム・勇者の詳細の HTML。引退した勇者の詳細も）を書き出す（冒険は進めない） |
| `scripts/rpg.py` | 勇者を登録・引退させ、現役の勇者を 1 日分ずつ進めて、状態とランキングの Gist（`hero-ranking.txt`）を更新する（詳細と地図はサイト） |
| `.state/heroes.json` | 勇者管理シート（勇者の一覧） |
| `.state/board.json` | ランキングの Gist の ID と URL |
| `.state/guild.json` | 町ごとのギルドの掲示板（日をまたいで残る。受付中・受注中・達成・失敗） |
| `.state/heroes/<id>.json` | 勇者ごとの状態・持ち物・日誌・シーズンの記録（形式は [docs/STATE_FORMAT.md](docs/STATE_FORMAT.md)） |
| `.github/workflows/hero-adventure.yml` | 毎日 JST 7:17 に rpg.py を動かし（ランキングの Gist を更新）、`.state/` と `heroes/` をコミットする |
| `.github/workflows/new-game.yml` / `retire-hero.yml` | 勇者の追加・引退（手動実行） |
| `.github/workflows/pages.yml` | CI（Ruff のリンター・フォーマット、テスト）と、サイトの公開。PR では CI だけ、master への push と毎日の実行・勇者の登録・引退のあとは CI が通ったら（CI と公開は同じコミットで行う） website.py でサイトを書き出して GitHub Pages に公開する（Settings → Pages の Source は「GitHub Actions」） |

```sh
python scripts/rpg.py --dry-run --actions 4       # 記録せずに今日の分を試す（行動回数を指定。勇者が登録済みのとき）
python scripts/rpg.py --new-game 名前              # 勇者を登録する（Actions の New game と同じ）
python scripts/rpg.py --retire 名前またはID        # 勇者を引退させる
python scripts/rpg.py --map-grid /tmp/grid.svg    # 座標の目盛りつきの確認用の地図（場所の pos を決めるときに）
python scripts/website.py /tmp/site               # サイトを書き出す（ブラウザで /tmp/site/index.html を開いて確かめる）
```
