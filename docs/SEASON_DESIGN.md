# シーズン制 RPG の設計（プロトタイプ）

今の「一本道を進んで魔王を倒す RPG」を、**MAP の上で勇者たちがギルドの依頼をこなし、アイテムを集めながら育っていくのを眺める RPG** に作り替えるための設計です。
まだプロトタイプの段階で、動かしながら調整する前提です。数値はすべて仮の値です。

## コンセプト

- 目的（ゴール）はない。勇者はそれぞれ勝手に動き、成長していく。それを眺める
- 毎日、町のギルドが依頼を出す。勇者はレベルに合った依頼を受けて、討伐・配達・ダンジョン探索などをこなす
- ダンジョンにはボスやレア装備がある（出たり、出なかったり）
- 3 か月で 1 シーズン。シーズンが変わるとレベルなどは最初に戻るが、**アイテムは持ち越す**
- MAP・ダンジョン・依頼は、データファイルを足して少しずつ広げていく

## 決まっていること・決まっていないこと

| 項目 | 方針 |
|---|---|
| シーズンの長さ | まず 3 か月（設定で変えられる） |
| 持ち越すもの | アイテムだけ。レベル・経験値・所持金・回復薬・位置・依頼はリセット |
| アイテムの釣り合い | レベルのリセットで取る。アイテムは多少のハンデ程度で、「アイテムが強い＝最強」にはしない |
| 力尽きたとき | 受けていた依頼が失敗になり、最後に寄った町に戻る（所持金は減らない） |
| 1 日の進み方 | 歩数ではなく行動回数 |
| Pin のカード | MAP は出さない。Gist はランキング（レベル・討伐数・依頼達成）の 1 つだけ。勇者ごとの詳細と地図はサイト（GitHub Pages）で見る |
| シーズン 1 の開始 | 第 1 段階ができてから |
| シナリオ（連続した依頼・世界の出来事） | **未定**。当面はランダムな探索とギルドの依頼だけ |
| 勇者の人数 | 現役は最大 30 人 |
| 勇者どうしの関わり | 当面はなし（同じ MAP・同じ掲示板を共有するだけ） |
| ギルドランク・称号 | 当面はなし |

## 世界の構造

### ワールド MAP

MAP は**場所（ノード）と道（エッジ）のつながり**として持つ。座標や 2 次元の絵は持たない（画面に MAP を描かないため）。

| 場所の種類 | すること |
|---|---|
| `town`（町） | HP の全回復、ギルド（依頼の受注・報告）、店（回復薬） |
| `field`（野外） | 通ると敵や宝箱などの出来事が起きる |
| `dungeon`（ダンジョンの入口） | ダンジョン用の MAP に入る |

- 道には距離（移動にかかる行動回数）がある
- 場所ごとに敵の顔ぶれと「危険度（推奨レベル）」を持つ。依頼の行き先の選び方と、敵の強さの目安に使う
- 移動は最短経路で進む。移動の途中で、通っている場所の出来事が起きる

### ダンジョン

ワールド MAP の `dungeon` の場所から入る、別の MAP。ダンジョンは用意したものを使う（自動生成はしない）。

- いくつかの階でできていて、各階に部屋がいくつかある。部屋を 1 つ探索するのに 1 行動かかる
- 部屋の出来事は、戦闘・宝箱・罠・何もない、のどれか（重みは階ごと）
- その階の部屋を探索し終えたら次の階へ進める。最下層にボスがいる
- 宝箱とボスは、ドロップ表（`none` を含む重み付き）から抽選する。レア装備は出たり、出なかったりする
- 外へ出るときは、今いる階の数だけ行動回数を使う（「帰り道」）
- 探索の途中経過（今いる階・部屋）は勇者の状態に持つ。シーズンが変わったら消す

## 1 日の流れ

毎日、勇者ごとに決まった**行動回数**（`actions_per_day`、今は 3 回）を使い切るまで、次の判断を繰り返す。何が起きるか（魔物・宝箱・景色など）は乱数で決まる。
行動回数が 0 の日は休む（HP が最大 HP の `rest_heal_rate`（25%）回復する。今は毎日 3 回なので起きない）。

```
1 行動ごとに:
  道を歩いている → 1 行動ぶん進む（HP が 30% 未満で回復薬もなく、この道で歩いた距離が残りより短ければ、先に道の手前の町へ引き返す）
  依頼を受けていない
    今日まだ受けていない → ギルドで依頼を選んで受ける（受けられるものがなければ、となりの町へ旅に出る）
    今日もう受けた     → 町の周りを散策する（道の出来事だけ。町からは動かない）
  討伐の依頼 → 行き・討伐・帰りを 1 行動ぶん進める
  配達・旅   → 目的の町へ向かう。目的を果たしたら、報告する町へ向かう（旅は報告しない）
  町に着いた → 依頼の報告（報酬を受け取る）、HP の全回復、買い物
```

### 依頼の進め方

依頼に期限はない（必要な行動力をこなせば終わる）。ふつう、失敗するのは力尽きたときだけ（ほかに、受けた勇者が引退したなどで依頼を持っていないとき、毎日の実行の最後に掲示板の依頼を失敗にする）。

| 場面 | どうなるか |
|---|---|
| 回復薬 | 戦いで HP が 0 になりそうなとき、自動で使う（最大 HP の `potion.heal_rate`（50%）まで回復）。町の店で `potion.keep`（3）個まで買い足す |
| 引き返す | 道を歩いているとき（配達・旅）だけ。HP が最大 HP の `retreat_hp_rate`（30%）未満で回復薬もなく、比べるのは今歩いている道だけで、この道で歩いた距離が残りより短ければ、道の手前の町（その道に入った町）へ戻る。依頼はそのまま続き、町で全回復してからまた向かう。町をいくつも通る配達でも、依頼を受けた町までは戻らない |
| 討伐の途中 | 引き返さない。行き・討伐・帰りを、終わるか力尽きるまで続ける |
| 散策の途中 | 町から動かないので、引き返すことはない |
| 力尽きた | 最後に寄った町（`home_town`）で目を覚ます（HP 全回復。所持金・持ち物・回復薬は減らない）。受けていた依頼は失敗になり、その日はそれ以上行動しない。力尽きた回数が 1 増える |
| 依頼の失敗 | 報酬（経験値・お金・アイテム）はもらえない。それまでの戦いで手に入れた経験値・お金・アイテムは残る。失敗した依頼の数が 1 増える（旅は数えない）。依頼を受けるのは 1 日 1 回なので、その日はもう受けられない |
| 掲示板の依頼 | 失敗した依頼は、その日は「失敗」になり、翌朝、最初の状態（段取り・行動力・報酬）に作り直して受付中に戻る（誰でも受けられる）。world/ から消えた依頼は戻らずはがす。旅は掲示板の依頼ではないので戻らない |

### ギルドの依頼

依頼の掲示板は**町ごとに 1 つ**で、全員で共通にする（新しく貼る依頼の乱数の種は「日付＋シーズン＋町の ID」）。
掲示板の枠は町ごとに決まっていて（`quests_per_day`）、貼られた依頼は日をまたいで残る（`.state/guild.json`）。誰も受けないまま `quest_open_days`（3）日たった依頼は入れ替わり、受注中の依頼はほかの勇者は受けられない（期限はない）。達成された依頼は翌日に新しい依頼に入れ替わり、失敗した依頼は翌日に同じ依頼が受付中に戻る。

| 種類 | 目的 | 例 |
|---|---|---|
| `hunt`（討伐） | 指定した場所で、指定した敵を指定の数だけ倒す | 「北の草原でウルフを 3 体」 |
| `deliver`（配達） | 別の町へ荷物を届ける。報告は届け先の町で行うので、着いた町で次の依頼を受けることになる | 「港町へ薬草を届ける」 |
| `explore`（探索） | ダンジョンの指定の階まで行く | 「古い坑道の B3F まで」 |
| `boss`（ボス） | ダンジョンのボスを倒す | 「氷の洞窟の氷竜を討伐」 |
| `special`（特別） | まれに出る大きな依頼。報酬にレア装備が確定で入る | 「魔王の影を討て」 |

- 依頼のひな形は `quests.json` に置き、**推奨レベルの範囲**を持つ。掲示板には、その町の周りの場所に合うものを数件並べる
- 勇者は、自分のレベルが推奨範囲に入る依頼の中から、報酬と距離を見て選ぶ（多少のランダムあり）
- 報酬は経験値・お金、それにアイテムが当たる確率

## アイテム

- 部位は `weapon`（武器）・`helmet`（兜）・`shield`（盾）・`accessory`（装飾品）の 4 か所（鎧はない）
- 珍しさ（`rarity`）は `common` / `rare` / `epic` / `legendary`。カードや日誌での目立たせ方に使う
- common は店で売る（品ぞろえは `tools/worldgen/build_world.py` の `SHOP`。どの町も同じで、町ごとの特産はない）。宝箱からは common・お金・回復薬だけが出る
- レア（rare 以上）は、`items.json` の `towns` に書いた町のギルドの依頼の報酬でしか出ない。レベルの制限はなく、出やすさはドロップ表の重み（`quests.json` の `reward.item`）で決める
- 手に入れたアイテムはすべて持ち物に入り、**部位ごとにいちばん強いものを自動で装備する**
- シーズンをまたいで持ち物を持ち越す。同じアイテムは重ねず、個数だけ数える

### 釣り合いの目安

アイテムは「多少のハンデ」にとどめ、強さの中心はレベルにする。目安は次のとおりで、**データを検証するテスト**で確かめる。

- アイテムの強さは点数で決める（`season.json` の `item_points`。攻 1・防 0.5・速 0.5・器 0.2・HP 0.2 点、属性 1 点で、マイナスも同じ点数で引く。点数の上限は ★ 1・★★ 2・★★★ 2・★★★★ 3。属性は ★★ から、スキルは ★★★ から）。決め方は docs/BALANCE.md の「8. アイテムの強さ」
- Lv1 の勇者が最強の装備をつけても、推奨レベルが大きく上の場所では勝てない（シミュレーションで確認）

---

## シーズン

- 長さは設定（`season.json`）で持つ。まず 3 か月で、区切りはカレンダーの四半期（例：12/1〜2/28）
- 乱数の種にシーズンの番号を入れる（「日付＋シーズン＋勇者の ID」）
- シーズンが変わった最初の実行で、勇者ごとに次を行う
  1. そのシーズンの記録を残す（最高レベル、達成した依頼の数、倒したボス、手に入れたレア装備、力尽きた回数）
  2. レベル・経験値・HP・所持金・回復薬・位置・依頼・ダンジョンの途中経過を最初の状態に戻す
  3. 持ち物（アイテム）はそのまま残す
- シーズンの途中で登録された勇者は、そのシーズンの途中から始まる（持ち物なし）

## データファイルの構成

1 ファイルの `rpg_world.json` をやめ、`world/` の下に種類ごとに分ける。**ダンジョンなどを足すときは、ファイルを足すか、一覧に 1 件足すだけ**で済むようにする。

```
world/
  season.json          シーズンの長さ・1 日の行動回数・初期ステータス・レベルアップの伸び
  map.json             場所（町・野外・ダンジョンの入口）と道
  monsters.json        敵の一覧
  items.json           アイテムの一覧
  quests.json          依頼のひな形
  dungeons/<id>.json   ダンジョン 1 つにつき 1 ファイル
```

参照はすべて**名前ではなく ID** で行う（名前を変えても状態が壊れないように）。

### 例: map.json

```json
{
  "starts": ["town_hajimari", "town_fusha"],
  "places": [
    {"id": "town_hajimari", "type": "town", "name": "はじまりの村", "emoji": "🏠"},
    {"id": "field_north", "type": "field", "name": "北の草原", "emoji": "🌱", "level": [1, 5],
     "monsters": ["slime", "wolf"], "events": {"battle": 50, "treasure": 10, "nothing": 40}},
    {"id": "dg_old_mine", "type": "dungeon", "name": "古い坑道", "emoji": "⛏️", "dungeon": "old_mine"}
  ],
  "roads": [
    {"from": "town_hajimari", "to": "field_north", "distance": 1},
    {"from": "field_north", "to": "dg_old_mine", "distance": 2}
  ]
}
```

### 例: dungeons/old_mine.json

```json

```

### データの検証（テスト）

手で編集するデータの誤りは、毎日の実行の最初にあるテストで止める（テストが失敗すると、その日の冒険は進まない）。エラーには、どのファイルのどの項目かを出す。

- 存在しない ID を参照していない
- ワールド MAP がつながっている（どの場所にも町から行ける）
- レベルの範囲・重み・距離が正の値
- アイテムの強さが「釣り合いの目安」を超えていない

データからダンジョンや場所を消しても、勇者の状態は壊さない。読み込むときに、消えた場所にいる勇者はスタートの町へ戻し、消えた依頼は取り消す。

## 作る順番

毎日の実行を止めないように、段階を分けて作る。

1. **第 1 段階**: ワールド MAP（町・野外・道）、ギルドの依頼（討伐・配達）、行動回数、アイテムと持ち物、シーズンの切り替え、新しいカードと本文、データの検証テスト、調整用のシミュレーション
2. **第 2 段階**: ダンジョン（階・部屋・ボス・ドロップ表）、探索とボスの依頼
3. **第 3 段階**: 特別な依頼（魔王など）、シナリオ（中身は未定）

第 1 段階が動いた時点でシーズン 1 を始める。その時点で今の勇者の状態ファイルは新しい形式で作り直す（今の冒険の記録は引き継がない）。
`heroes.json`・Gist・毎日の workflow・勇者の追加と引退・実行されなかった日の取り戻しは、今の仕組みをそのまま使う。

## 実装の状況

**第 1 段階を実装済み**（`world/`・`scripts/world.py`・`scripts/game.py`・`scripts/rpg.py`）。設計から変えた点・補った点:

**世界（オルドラ）**: 設定は docs/WORLD.md。場所は町 25 とダンジョン 7（まだ入れない）。野外の場所は置かない。
世界は少しずつ開放する。いまは南大陸の 4 町（`map.json` の `open`）だけで、ほかの町への道は描かず通れない。開放していない町の依頼とレア以上のアイテムはデータから外している。
町と町は陸路と航路でつながり、道ごとに移動にかかる行動回数（distance）と地形の割合（terrain）を持つ。
道を 1 行動進むごとに出来事（戦闘・宝箱・景色）が起き、魔物は道の地形の魔物のうち、勇者の Lv −3〜+1 の魔物から選ぶ（#145）。魔物は種類ごとに Lv1〜15 の強さがあり（#124・#145）、地形ごとに出る魔物と性質が違う。
最初の町は 6 つの町からランダム（勇者とシーズンごと）。
地図はサイトの地図のページ（map.html）に、地図の画像（1600×1000、北が上。ベースの地図 world/map-base.svg の上に町・ダンジョン・道・行動回数・勇者）として埋め込む。

- データファイルは `season.json`・`map.json`・`monsters.json`・`items.json`・`quests.json`（`dungeons/` は第 2 段階で足す）
- 町の店では回復薬に加えて、今より良い装備（`price` のあるアイテム）も買う。回復薬の分のお金は残して買う
- 依頼がないときは、となりの町へ「旅」をする（報酬なし・期限なし）。これで勇者は世界に散らばっていく
- 依頼を受けるのは 1 日 1 回（受けるのに行動回数は使わない）。依頼ごとに必要な行動力があり、毎日の行動回数でこなす。終わってその日の行動回数が余ったら、町の周りを散策する（道の出来事だけ）
- 討伐の依頼は「行き（狩り場まで。道の長さの半分、最大 2）→ 討伐（1 行動で目的の魔物と 1 回戦う）→ 帰り」。行き・帰りは道の出来事が起きる。勇者は町から動かない（地図では狩り場の位置に出す）
- 配達の必要な行動力は、届け先までの距離。ダンジョン探索を伴う討伐（ダンジョンまでの距離＋探索＋討伐＋帰り）は、ダンジョンを作るときに足す
- 受けられる依頼は「推奨レベルの下限 ≤ 自分のレベル＋3」（討伐の推奨レベルは狙う魔物のレベル、配達は魔物のいちばん多いレベル）。掲示板の中から均等に選ぶ
- 掲示板は町ごとに `quests_per_day` 件（ギルドの規模。どの町にも書く）。依頼は早い者勝ちで、ほかの勇者が受けた依頼は受けられない（`.state/guild.json`）。掲示板の枠は町ごとに決まっていて（`quests_per_day`）、貼られた依頼は日をまたいで残る（`.state/guild.json`）。誰も受けないまま `quest_open_days`（3）日たった依頼は入れ替わり、受注中の依頼はほかの勇者は受けられない（期限はない）。達成された依頼は翌日に新しい依頼に入れ替わり、失敗した依頼は翌日に同じ依頼が受付中に戻る。受けられる依頼がなければ、となりの町へ旅に出る。毎日、勇者を進める順番を日付で混ぜ、さかのぼって進めるときも 1 日ずつ全員をそろえて進める
- 枠ごとにレアリティ（★ 60・★★ 25・★★★ 12・★★★★ 3 の重み）を選び、その町の依頼から選ぶ（その町にないレアリティは 1 つ下に落とす。町の依頼は 1 日に 1 度だけ）。足りない枠には共通の依頼が入る
- 報酬は「1 行動あたりの報酬（`quests.json` の `reward`。経験値 5・お金 8）× 必要な行動力 × レアリティの倍率（1・2・4・8）」。討伐も配達も、行動力が同じなら報酬も同じ（討伐は別に、1 体ごとの戦闘の経験値とお金が入る）。アイテムはレアリティごとのドロップ表から、依頼を出した町のものが出る
- 魔物の経験値は、勇者とのレベル差では変わらない（レベル差 4 以上で減らす仕組みは #124 でやめた。地方を増やすときに、低レベルの場所に居座らないか見直す）
- `season.json` の `start` より前の日はシーズン 1 に含める（いま動かし始めれば、そのまま 1 シーズン目になる）
- 前の形式の状態ファイルは、読み込むときに新しい形式で最初から作り直す

1 シーズン（90 日）を勇者 80 人でシミュレーションした結果（現在のデータ）:

| 指標 | 結果 |
|---|---|
| シーズン末のレベル | 最小 10 / 中央値 10 / 最大 11（魔物の強さがどこでも同じなので、ここで頭打ちになる） |
| 達成した依頼 | 中央値 23（成功率 99%） |
| 力尽きた回数 | 中央値 0 |
| 手に入れたレア | 中央値 2（0〜5） |

いまは「回してみてから決める」段階。強い敵（ダンジョン）が入るまでは、力尽きることはほとんどない。

## 調整で見ること

今の「まとめてシミュレーションするテスト」と同じやり方で、勇者を何十人か 3 か月分動かして確かめる。

- シーズンの終わりのレベルが、ばらつきつつも狙いの範囲に収まる
- 依頼の成功率が高すぎず低すぎない（例: 7〜8 割）
- レア装備が 1 シーズンに数個出る程度
- 「何も起きない日」が続かない
