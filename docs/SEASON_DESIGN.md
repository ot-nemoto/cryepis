# シーズン制 RPG の設計（プロトタイプ）

今の「一本道を進んで魔王を倒す RPG」を、**MAP の上でもののふたちが口入れ屋の依頼をこなし、武具を集めながら育っていくのを眺める RPG** に作り替えるための設計です。
まだプロトタイプの段階で、動かしながら調整する前提です。数値はすべて仮の値です。

## コンセプト

- 目的（ゴール）はない。もののふはそれぞれ勝手に動き、成長していく。それを眺める
- 毎日、町の口入れ屋が依頼を出す。もののふはレベルに合った依頼を受けて、討伐・配達・霊場探索などをこなす
- 霊場には主やレア装備がある（出たり、出なかったり）
- 3 か月で 1 シーズン。シーズンが変わるとレベルなどは最初に戻るが、**武具は持ち越す**
- MAP・霊場・依頼は、データファイルを足して少しずつ広げていく

## 決まっていること・決まっていないこと

| 項目 | 方針 |
|---|---|
| シーズンの長さ | まず 3 か月（設定で変えられる） |
| 持ち越すもの | 武具だけ。レベル・経験値・所持金・丸薬・位置・依頼はリセット |
| 武具の釣り合い | レベルのリセットで取る。武具は多少のハンデ程度で、「武具が強い＝最強」にはしない |
| 力尽きたとき | 受けていた依頼が失敗になり、最後に寄った町に戻る（所持金は減らない） |
| 1 日の進み方 | 歩数ではなく行動回数 |
| Pin のカード | MAP は出さない。Gist は番付（レベル・討伐数・依頼達成）の 1 つだけ。もののふごとの詳細と絵図はサイト（GitHub Pages）で見る |
| シーズン 1 の開始 | 第 1 段階ができてから |
| シナリオ（連続した依頼・世界の出来事） | **未定**。当面はランダムな探索と口入れ屋の依頼だけ |
| もののふの人数 | 現役は最大 30 人 |
| もののふどうしの関わり | 当面はなし（同じ MAP・同じ高札を共有するだけ） |
| 口入れ屋ランク・称号 | 当面はなし |

## 世界の構造

### ワールド MAP

MAP は**場所（ノード）と道（エッジ）のつながり**として持つ。座標や 2 次元の絵は持たない（画面に MAP を描かないため）。

| 場所の種類 | すること |
|---|---|
| `town`（町） | 旅籠（休憩すると 1 行動と 20文で HP が全回復）、口入れ屋（依頼の受注・報告）、店（丸薬） |
| `field`（野外） | 通ると敵や宝箱などの出来事が起きる |
| `dungeon`（霊場の入口） | 霊場用の MAP に入る |

- 道には距離（移動にかかる行動回数）がある
- 場所ごとに敵の顔ぶれと「危険度（推奨レベル）」を持つ。依頼の行き先の選び方と、敵の強さの目安に使う
- 移動は最短経路で進む。移動の途中で、通っている場所の出来事が起きる

### 霊場

ワールド MAP の `dungeon` の場所から入る、別の MAP。霊場は用意したものを使う（自動生成はしない）。

- いくつかの階でできていて、各階に部屋がいくつかある。部屋を 1 つ探索するのに 1 行動かかる
- 部屋の出来事は、戦闘・宝箱・罠・何もない、のどれか（重みは階ごと）
- その階の部屋を探索し終えたら次の階へ進める。最下層に主がいる
- 宝箱と主は、ドロップ表（`none` を含む重み付き）から抽選する。レア装備は出たり、出なかったりする
- 外へ出るときは、今いる階の数だけ行動回数を使う（「帰り道」）
- 探索の途中経過（今いる階・部屋）はもののふの状態に持つ。シーズンが変わったら消す

## 1 日の流れ

毎日、もののふごとに決まった**行動回数**（`actions_per_day`、今は 3 回）を使い切るまで、次の判断を繰り返す。何が起きるか（物の怪・宝箱・景色など）は乱数で決まる。
行動回数が 0 の日は休む（HP が最大 HP の `rest_heal_rate`（25%）回復する。今は毎日 3 回なので起きない）。

```
1 行動ごとに:
  道を歩いている → 1 行動ぶん進む（HP が減っても引き返さない）
  依頼を受けていない
    HP が性格の旅籠の割合未満 → 旅籠で休憩する（1 行動と旅籠代で全回復）
    町に着いてから stay_days_max（7）日たった → 依頼を受けずに、となりの町へ旅に出る（#231）
    今日まだ受けていない → 口入れ屋で性格に合う依頼を選んで受ける（配達は Lv を見ない。Lv の範囲に合う依頼がなければ、範囲より弱い依頼のうち
                           いちばん近い Lv のもの。#228。それもなければ、となりの町へ旅に出る）
    今日もう受けた     → 性格で決まった行動: 休む（行動力を溜める）・散策する（町からは動かない）・となりの町へ移動する
  討伐の依頼 → 行き・討伐・帰りを 1 行動ぶん進める
  配達・旅   → 目的の町へ向かう。目的を果たしたら、報告する町へ向かう（旅は報告しない）
  町に着いた → 依頼の報告（報酬を受け取る）、買い物（HP は回復しない）
今日の行動回数を使い切ったとき、依頼の途中なら、溜めた行動力を使って続ける（旅籠の休憩にも使う）
```

### 依頼の進め方

依頼に期限はない（必要な行動力をこなせば終わる）。ふつう、失敗するのは力尽きたときだけ（ほかに、受けたもののふが引退したなどで依頼を持っていないとき、毎日の実行の最後に高札の依頼を失敗にする）。

| 場面 | どうなるか |
|---|---|
| 丸薬 | 戦いで HP が性格の `potion_below` の割合を下回ったら、自動で使う（最大 HP の `potion.heal_rate`（50%）ぶん回復。最大 HP は超えない）。HP が 0 になったら、丸薬があっても力尽きる。町の店で、性格の `potions_first` 個まで装備より先に買い、装備のあと `potion.keep`（3）個まで買い足す（性格のないもののふ＝シミュレーターは、前のとおり倒れる前に使う） |
| 旅籠 | 依頼を持っていないとき、HP が性格の `inn_below` の割合を下回っていたら、旅籠で休憩する（1 行動と `inn.price`（20文）で全回復）。町に着いても回復しない（#95） |
| 行動力を溜める | 性格が「休む」なら、その日の残りの行動を溜める（`stored_days`（2）日分まで。HP は回復しない）。依頼の途中で今日の行動回数を使い切ったときと、旅籠の休憩に使う。シーズンが変わると 0 に戻る |
| 引き返す | 引き返さない（#174 で引き返す動きを消した）。配達・旅・討伐のどれも、HP が減っても依頼が終わるか力尽きるまで進む |
| 散策 | 町から動かない。散策だけの表（`stroll_events`: 戦闘 30%・強い物の怪（Lv +2〜+3。`stroll_strong_levels`）5%・宝箱 15%・何もない 50%。宝箱は `stroll_treasure`: 装備 10%・丸薬 25%・お金 65%。お金は道の宝箱と同じく `treasure_gold` の 10〜30文）（#226） |
| 力尽きた | 最後に寄った町（`home_town`）で目を覚ます（HP 全回復。所持金・持ち物・丸薬は減らない）。受けていた依頼は失敗になり、その日はそれ以上行動しない。力尽きた回数が 1 増える |
| 依頼の失敗 | 報酬（経験値・お金・武具）はもらえない。それまでの戦いで手に入れた経験値・お金・武具は残る。失敗した依頼の数が 1 増える（旅は数えない）。依頼を受けるのは 1 日 1 回なので、その日はもう受けられない |
| 高札の依頼 | 失敗した依頼は、その日は「失敗」になり、翌朝、最初の状態（段取り・行動力・報酬）に作り直して受付中に戻る（誰でも受けられる）。world/ から消えた依頼は戻らずはがす。旅は高札の依頼ではないので戻らない |

### 口入れ屋の依頼

依頼の高札は**町ごとに 1 つ**で、全員で共通にする（新しく貼る依頼の乱数の種は「日付＋シーズン＋町の ID」）。
高札の枠は町ごとに決まっていて（`quests_per_day`）、貼られた依頼は日をまたいで残る（`.state/guild.json`）。誰も受けないまま `quest_open_days`（3）日たった依頼は入れ替わり、受注中の依頼はほかのもののふは受けられない（期限はない）。達成された依頼は翌日に新しい依頼に入れ替わり、失敗した依頼は翌日に同じ依頼が受付中に戻る。

| 種類 | 目的 | 例 |
|---|---|---|
| `hunt`（討伐） | 指定した場所で、指定した敵を指定の数だけ倒す | 「北の草原でウルフを 3 体」 |
| `deliver`（配達） | 別の町へ荷物を届ける。報告は届け先の町で行うので、着いた町で次の依頼を受けることになる | 「港町へ薬草を届ける」 |
| `explore`（探索） | 霊場の指定の階まで行く | 「古い坑道の B3F まで」 |
| `boss`（主） | 霊場の主を倒す | 「氷の洞窟の氷竜を討伐」 |
| `special`（特別） | まれに出る大きな依頼。報酬にレア装備が確定で入る | 「魔王の影を討て」 |

- 依頼のひな形は `quests.json` に置き、**推奨レベルの範囲**を持つ。高札には、その町の周りの場所に合うものを数件並べる
- もののふは、自分のレベルが推奨範囲に入る依頼の中から、報酬と距離を見て選ぶ（多少のランダムあり）
- 報酬は経験値・お金、それに武具が当たる確率

## 武具

- 部位は `weapon`（武器）・`helmet`（頭）・`shield`（胴）・`accessory`（御守）の 4 か所
- 珍しさ（`rarity`）は `common` / `rare` / `epic` / `legendary`。カードや日誌での目立たせ方に使う
- ★の武具（common）は店で売る。★★（rare）は散策・移動の宝箱と通常の依頼報告から出る。確率は `season.json` の宝箱の表と `quests.json` の `ranks[].item` に置く
- 大物・主の討伐で原石を受け取るのは参加者から均等に抽選した 1 人。残りの参加者にはそれぞれ ★★★（epic）の武具を 1 つ渡す。主の武具には、固定スキルに加えて部位に合うランダムな追加スキルが付く
- 手に入れた武具はすべて持ち物に入り、**部位ごとにいちばん強いものを自動で装備する**
- シーズンをまたいで持ち物を持ち越す。同じ武具は重ねず、個数だけ数える

### 釣り合いの目安

武具は「多少のハンデ」にとどめ、強さの中心はレベルにする。目安は次のとおりで、**データを検証するテスト**で確かめる。

- 武具の強さは点数で決める（`season.json` の `item_points`。攻 1・防 0.5・速 0.5・器 0.2・HP 0.2 点、属性 1 点で、マイナスも同じ点数で引く。点数の上限は ★ 1・★★ 2・★★★ 2・★★★★ 3。属性は ★★ から、スキルは ★★ から（#233。点数には入れない）。★★★・★★★★ の固定スキルは docs/WORLD.md の「3. 店の品とレア」。★★★★は地方の名工の鍛冶屋で、その地方の原石 10 個と 10,000 文を使って 1 日 1 回生成する。行動回数は使わず、4 部位から均等に選ぶ。7 地方の原石名と性質は docs/WORLD.md に定義し、原石自体には数値効果を持たせない。現在、生成できるのは坂東だけ）。決め方は docs/BALANCE.md の「8. 武具の強さ」
- Lv1 のもののふが最強の装備をつけても、推奨レベルが大きく上の場所では勝てない（シミュレーションで確認）

## シーズン

- 長さは設定（`season.json`）で持つ。まず 3 か月で、区切りはカレンダーの四半期（例：12/1〜2/28）
- 乱数の種にシーズンの番号を入れる（「日付＋シーズン＋もののふの ID」）
- シーズンが変わった最初の実行で、もののふごとに次を行う
  1. そのシーズンの記録を残す（最高レベル、達成した依頼の数、倒した主、手に入れたレア装備、力尽きた回数）
  2. レベル・経験値・HP・所持金・丸薬・位置・依頼・霊場の途中経過を最初の状態に戻す
  3. 持ち物（武具）はそのまま残す
- シーズンの途中で登録されたもののふは、そのシーズンの途中から始まる（持ち物なし）

## データファイルの構成

1 ファイルの `rpg_world.json` をやめ、`world/` の下に種類ごとに分ける。**霊場などを足すときは、ファイルを足すか、一覧に 1 件足すだけ**で済むようにする。

> 以降の JSON は設計時の**例**で、ID や項目は実装と違う。実際のデータは `world/`（[WORLD.md](WORLD.md)）、状態の形式は [STATE_FORMAT.md](STATE_FORMAT.md) を見る。

```
world/
  season.json          シーズンの長さ・1 日の行動回数・初期ステータス・レベルアップの伸び
  map.json             場所（町・野外・霊場の入口）と道
  monsters.json        敵の一覧
  items.json           武具の一覧
  quests.json          依頼のひな形
  dungeons/<id>.json   霊場 1 つにつき 1 ファイル
```

参照はすべて**名前ではなく ID** で行う（名前を変えても状態が壊れないように）。

### 例: map.json

```json
{
  "starts": ["town_hajimari", "town_fusha"],
  "places": [
    {"id": "town_hajimari", "type": "town", "name": "はじまりの村", "emoji": "🏠"},
    {"id": "field_north", "type": "field", "name": "北の草原", "emoji": "🌱", "level": [1, 5],
     "monsters": ["slime", "wolf"], "events": {"battle": 50, "treasure": 10, "nothing": 40}},
    {"id": "dg_old_mine", "type": "dungeon", "name": "古い坑道", "emoji": "⛏️", "dungeon": "old_mine"}
  ],
  "roads": [
    {"from": "town_hajimari", "to": "field_north", "distance": 1},
    {"from": "field_north", "to": "dg_old_mine", "distance": 2}
  ]
}
```

### 例: dungeons/old_mine.json

```json
{
  "id": "old_mine", "name": "古い坑道", "level": [4, 10],
  "floors": [
```

### 例: quests.json

```json

    {"id": "hunt_basic", "type": "hunt", "level": [1, 6], "count": [2, 4], "days": 3,

    {"id": "deliver", "type": "deliver", "level": [1, 99], "days": 5,
     "reward": {"exp": 10, "gold": 50}, "text": "{town}へ荷物を届ける"}
  ]
}
```

### データの検証（テスト）

手で編集するデータの誤りは、毎日の実行の最初にあるテストで止める（テストが失敗すると、その日の冒険は進まない）。エラーには、どのファイルのどの項目かを出す。

- 存在しない ID を参照していない
- ワールド MAP がつながっている（どの場所にも町から行ける）
- レベルの範囲・重み・距離が正の値
- 武具の強さが「釣り合いの目安」を超えていない

データから霊場や場所を消しても、もののふの状態は壊さない。読み込むときに、消えた場所にいるもののふはスタートの町へ戻し、消えた依頼は取り消す。

## 作る順番

毎日の実行を止めないように、段階を分けて作る。

1. **第 1 段階**: ワールド MAP（町・野外・道）、口入れ屋の依頼（討伐・配達）、行動回数、武具と持ち物、シーズンの切り替え、新しいカードと本文、データの検証テスト、調整用のシミュレーション
2. **第 2 段階**: 霊場（階・部屋・主・ドロップ表）、探索と主の依頼
3. **第 3 段階**: 特別な依頼（魔王など）、シナリオ（中身は未定）

第 1 段階が動いた時点でシーズン 1 を始める。その時点で今のもののふの状態ファイルは新しい形式で作り直す（今の冒険の記録は引き継がない）。
`heroes.json`・Gist・毎日の workflow・もののふの追加と引退・実行されなかった日の取り戻しは、今の仕組みをそのまま使う。

## 実装の状況

**第 1 段階を実装済み**（`world/`・`scripts/world.py`・`scripts/game.py`・`scripts/rpg.py`）。設計から変えた点・補った点:

**世界（日本の九州〜東北。和風に作り替え中、#247）**: 設定は docs/WORLD.md。場所は町 25 と霊場 7（まだ入れない）。野外の場所は置かない。
世界は少しずつ開放する。いまは坂東の 4 町（`map.json` の `open`）だけで、ほかの町への道は描かず通れない。開放していない町の依頼とレア以上の武具はデータから外している。
町と町は陸路と航路でつながり、道ごとに移動にかかる行動回数（distance）と地形の割合（terrain）を持つ。
道を 1 行動進むごとに出来事（戦闘・宝箱・景色）が起き、物の怪は道の両端の町がある地方の、道の地形に住む物の怪のうち、もののふの Lv −3〜+1 の物の怪から選ぶ（#145・#265・#267）。物の怪は種類ごとに Lv1〜15 の強さと性質があり（#124・#145）、地方ごとに出る物の怪が違う（7 地方 × Lv1〜15 × 2 体）。
最初の町は 6 つの町からランダム（もののふとシーズンごと）。
地図はサイトの絵図のページ（最初のページ index.html）に、地図の画像（1600×1000、北が上。ベースの地図 world/map-base.svg の上に町・霊場・道・行動回数・もののふ）として埋め込む。

- データファイルは `season.json`・`map.json`・`monsters.json`・`items.json`・`quests.json`（`dungeons/` は第 2 段階で足す）
- 町の店では丸薬に加えて、今より良い装備（`price` のある武具）も買う。順は性格で決まる（旅籠代を残す → 丸薬を `potions_first` 個 → 装備 → 丸薬を 3 個まで）
- 依頼がないときは、となりの町へ「旅」をする（報酬なし・期限なし）。これでもののふは世界に散らばっていく
- 依頼を受けるのは 1 日 1 回（受けるのに行動回数は使わない）。依頼ごとに必要な行動力があり、毎日の行動回数でこなす。終わってその日の行動回数が余ったら、性格で決まった行動（休む・散策する・となりの町へ移動する）をする
- 討伐の依頼（大物を含む）は「行き（狩り場まで。道の長さによらず 1 行動。#297）→ 討伐（何体いても 1 行動で、1 体ずつ連戦する。#165）→ 帰り（1 行動）」で、1 人 3 行動（大物の仲間待ちは別）。主の討伐は霊場への山道の行動回数で行き帰りする。道の戦いは 1 体だけ（何体かと戦うのは討伐だけ）。行き・帰りは道の出来事が起きる。もののふは町から動かない（地図では狩り場の位置に出す）
- 配達の必要な行動力は、届け先までのいちばん近い道のりの片道分。受注と報告は行動回数を使わない。霊場探索を伴う討伐（霊場までの距離＋探索＋討伐＋帰り）は、霊場を作るときに足す
- 受けられる依頼は、性格の Lv の範囲に入る討伐（討伐の Lv は狙う物の怪のレベル）と、すべての配達（配達は Lv を持たず、Lv を見ない。#150・#228）。範囲に合う依頼がなければ、範囲より弱い依頼のうちいちばん近い Lv のもの。選び方は性格で決まる（ランダムはなし）。性格のないもののふは「討伐の Lv ≤ 自分のレベル＋3」の中から均等に選ぶ
- 高札は町ごとに `quests_per_day` 件（口入れ屋の規模。どの町にも書く）。依頼は早い者勝ちで、ほかのもののふが受けた依頼は受けられない（`.state/guild.json`）。高札の枠は町ごとに決まっていて（`quests_per_day`）、貼られた依頼は日をまたいで残る（`.state/guild.json`）。誰も受けないまま `quest_open_days`（3）日たった依頼は入れ替わり、受注中の依頼はほかのもののふは受けられない（期限はない）。達成された依頼は翌日に新しい依頼に入れ替わり、失敗した依頼は翌日に同じ依頼が受付中に戻る。受けられる依頼がなければ、となりの町へ旅に出る。毎日、もののふを進める順番を日付で混ぜ、さかのぼって進めるときも 1 日ずつ全員をそろえて進める
- 枠ごとにレアリティ（★ 40・★★ 40・★★★ 10・★★★★ 10 の重み。#297）を選び、その町の依頼から選ぶ（その町にないレアリティは 1 つ下に落とす。町の依頼は 1 日に 1 度だけ）。★★★★ は大物の依頼だけなので、その町に大物を受けられるもののふがそろっていない枠では ★★★ に落ち、★★★ は実質 約 20% 出る（ユーザーの決定で、このままにした）。大物・主の決まりを変える前に貼られた・受けられた依頼（★・行動力・報酬が今と違うもの、消えた町の依頼）は捨て、受けていたもののふの日誌に取り下げを残す。足りない枠には共通の依頼が入る
- 報酬はお金だけ（#171。経験値は物の怪を倒したときだけ入る）。「1 行動あたりのお金（`quests.json` の `reward`。8文）× 必要な行動力 × レアリティの倍率（1・2・4・8）」で、配達はさらに `deliver_rate`（2）倍（討伐は別に、1 体ごとの戦闘の経験値とお金が入る）。何人かで受ける大物・主の達成報酬は、★と行動力によらず `reward` の `party_gold`（大物 160文・主 320文。参加した全員が受け取る。#297）。
- 共通の討伐（1〜5 体）の ★ は、点数 = 物の怪の Lv ×（数 + 1）で決める（#170。`quests.json` の `hunt_ranks` = [15, 40]。15 以下 ★・40 以下 ★★・それより上 ★★★）。高札では枠ごとに ★ を抽選し、その ★ になる物の怪と数を選ぶ（その道で作れなければ ★ を下げる）。★★★★ は大物・主の討伐用にとっておく（共通の依頼では作らない）。
- 討伐の連戦は、途中で HP を見ずに最後まで戦う（危なさは ★ で分かる。受けられるかどうかは物の怪の Lv だけで決まる）。討伐の行動力と報酬は数では変わらない（数は ★ の計算に入るので、★ が上がる分だけ報酬が増える）。どちらもユーザーが「今のまま」を選んだ（PR #169 のレビュー）。
- 討伐も決まった依頼を持たず、毎回作る（#173。町の決まった依頼は大物の討伐だけ）。名前は「{物の怪}の討伐」、説明は町の困りごと（`quests.json` の `hunts` の `places`）と ★ ごとの頼み方（`texts`）から作る。
- 配達は決まった依頼を持たず、町の荷物から作る（#172。`quests.json` の `deliveries`）。危なさ 0・1・2 で、運んでいる間の道の戦いでは出会う物の怪の Lv を +0・+2・+4（危なさ 2 は Lv5 から受けられる）。★ は 距離 ×（危なさ + 1）で、4 以下 ★・8 以下 ★★・それより上 ★★★。名前は「{荷物}の配達」、説明は危なさごとの文に荷物と届け先を入れる。★ は依頼の大きさの目安で、受けられるかどうかは Lv で決まる。武具はレアリティごとのドロップ表から、依頼を出した町のものが出る
- 物の怪の経験値は、もののふとのレベル差では変わらない（レベル差 4 以上で減らす仕組みは #124 でやめた。地方を増やすときに、低レベルの場所に居座らないか見直す）
- `season.json` の `start` より前の日はシーズン 1 に含める（いま動かし始めれば、そのまま 1 シーズン目になる）
- 前の形式の状態ファイルは、読み込むときに新しい形式で最初から作り直す

1 シーズン（90 日）をもののふ 80 人でシミュレーションした結果（現在のデータ）:

| 指標 | 結果 |
|---|---|
| シーズン末のレベル | 最小 10 / 中央値 10 / 最大 11（物の怪の強さがどこでも同じなので、ここで頭打ちになる） |
| 達成した依頼 | 中央値 23（成功率 99%） |
| 力尽きた回数 | 中央値 0 |
| 手に入れたレア | 中央値 2（0〜5） |

いまは「回してみてから決める」段階。強い敵（霊場）が入るまでは、力尽きることはほとんどない。

## 調整で見ること

今の「まとめてシミュレーションするテスト」と同じやり方で、もののふを何十人か 3 か月分動かして確かめる。

- シーズンの終わりのレベルが、ばらつきつつも狙いの範囲に収まる
- 依頼の成功率が高すぎず低すぎない（例: 7〜8 割）
- レア装備が 1 シーズンに数個出る程度
- 「何も起きない日」が続かない
